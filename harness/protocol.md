# 工作协议：先想清楚这一版要证明什么

> 这份协议是为我自己写的，因为同一个错误已经重复了四次 ——
> **拿到一句话就动手做最大的那个产物**，而不是先问「这一版要证明什么、最小的载体是什么」。

## 为什么需要它

这次会话里的真实轨迹（不是假设）：

| 我说了什么 | 我实际做了什么 | 代价 |
| --- | --- | --- |
| 「规划里批注：不该按验证工具去调生产参数」 | 转头按同一个坏习惯，把场景 demo 重做成 400 行 PAGX | 876 帧白烘 |
| 「要做 demo」 | 直接烘视频，没先问载体 | 用户要的是原型 |
| 「换成一个更好的工具会怎样」 | 又烘一版 29 秒视频 | 第二次白烘 |

**共同点**：没有一步是「先写下一句话说明这一版要证明什么」。
没有验收标准，产物就只能靠**表演**说服人 —— 这正是「demo 做成表演」的根源。

所以规则只有一条，而且是可被机器检查的一条：

> **动手之前，先写意图卡。卡上必须有一条能重跑的命令作为验收。**

## 意图卡：五个必填字段

放在 `harness/cards/<日期>-<短名>.md`：

```md
# <这一版做什么>

- 状态: 草稿 | 进行中 | 完成
- 产物: <会新增/改动的路径>

## 目标
这一版要证明的一件事。一句话。写不出来就说明还没想清楚。

## 验收
能重跑的命令，写在反引号里。例：`node verify/scenarios.mjs`
"看起来不错" 不算验收 —— 它不可重跑，也不可被反驳。

## 载体候选
至少两个，各带代价。**先选最便宜的那个。**
- 原型 HTML：改一行重看，0 成本，但不像成品
- 烘视频：876 帧 / 90 秒，且改一个词就要重来

## 不做什么
这一版明确不碰的东西。没有这一节，范围一定会膨胀。

## 诚实边界
这一版**不证明**什么。对外产物必须自带这一段。
```

## 机器怎么拦我

`node harness/check.mjs`（进 CI，也进 `npm run gate`）：

1. **卡要先于产物存在。** 用 git 的 add-commit 时间比对：
   产物比卡先提交 → 说明是**先做后补**，等于没想过。规则从闸门安装那一刻生效，
   之前的记为欠账（WARN），不追溯 —— 历史改不了，能改的只有以后。
2. **验收必须可重跑。** 含反引号命令才算；`状态: 完成` 时闸门**真的去跑它**。
3. **载体候选 ≥ 2。** 少于两个，说明没比较过，就不是选的是撞的。
4. **对外产物必须带诚实边界**（`<!-- harness:limits -->` 标记及其内容）。
   一件对外的东西如果不说清它不证明什么，它就只能靠表演成立。

## 反过来说，这套东西**不**拦什么

它不拦探索、不拦小改动、不拦一次性脚本。
它拦的是**同一个错误**：在不清楚要证明什么的情况下，一次性造一个大东西出来。

> 判断标准很朴素：**如果一个产物没法被一句话说清「它证明了什么」，那它就是在表演。**
