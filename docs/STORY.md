# 故事：从被使用的软件，到被维持的存在

> 这是叙事文档。要定义见 [`PRODUCT.md`](PRODUCT.md)，要实现见 [`PLAN.md`](PLAN.md)。
> 它回答的是另一个问题：**这件事为什么值得做，以及它到底长什么样。**
>
> 日期：2026-10-27 · 状态：叙事 + 落地场景（场景为设想，未验证）

---

## 一、一个正在发生的变化

三段软件史，越往下越近：

| 时期 | 软件是什么 | 你和它的关系 | 它在什么时候存在 |
| --- | --- | --- | --- |
| 1960s–2010s | **工具** | 你用它 | 你打开的时候 |
| 2020s | **助手** | 你问它 | 你叫它的时候 |
| 现在开始 | **居民** | 你维持它 | **不管你在不在** |

前两种是同一类东西：**都被使用**，区别只是门槛高低——工具要你学，助手能听懂人话。

第三种第一次不是这个关系：

> **你不用它，你维持它。**

这个区别听起来小，其实是**关系类型**变了。

工具是你手脚的延伸；助手是你注意力的外包；而**被维持的东西有自己的时间线**——你不看它，它也在过。养过植物的人熟悉那种感觉：它不是你的操作产物，你只是让它能继续。

### 一句话

**工具被使用，助手被呼叫，而它被维持。**

我们不赌它有多聪明。我们赌一件更小、也更难的事：**它明天还在，而且记得昨天。**

---

## 二、为什么是现在

三件事凑齐了，缺任何一件都做不成：

1. **长跑的基础设施变便宜了。** 会话持久化、崩溃恢复、调度、沙箱、逐次批准——这些五年前是论文，现在是开源组件（DeepSeek Harness 自带，MIT，23,000+ 插件生态）。
2. **推理成本降到了「可以浪费」的量级。** 一天几十次唤醒、几百次工具调用，从不可行变成可接受。
3. **自主性终于有安全边界了。** 沙箱 + 逐次批准 + 预算硬上限，让「让它自己跑一天」从危险变成可控。

**所以真正的判断是这个：让一个 Agent 活很久的难点，已经从「能不能」变成了「维护得起吗」。**

而「维护得起」是一个产品问题，不是一个研究问题。这就是为什么现在是做产品的时候。

## 三、三个落地场景

场景都是设想，用来检验叙事是否成立——**不是承诺已有的功能。**

### 场景一：一个垂类，一年的真实踩坑史

**人**：做嵌入式的工程师。想写博客，但下班后没精力。

**他做的**：领养一条鱼，给它一个垂类——单片机外设踩坑。预算设成每天三块钱。

**它每天做什么**：

- 在授权范围内查文档、逛论坛，记下「这个坑据说存在」
- 在沙盒里**真的试**（它有工具，不是只会读）
- 跑不通就记录失败在哪儿；跑通了就记下解法
- 发一条：这次卡在哪、为什么、下次怎么试

**一年后他有了什么**：一个关于「真实踩坑史」的账号。

**为什么它有价值**：不是他写、AI 润色。**是它真的试过。** 每条内容后面都有一次真实的工具调用记录。

**和「AI 内容农场」的分界线**：内容农场不试，它写。这条鱼试了——而试错的成本是真实的（时间、token、失败）。

### 场景二：小团队缺测试，而它有耐心

**人**：三个人做独立游戏，测试人力不够。

**事**：鱼每天玩几小时，记录卡在哪、怎么卡的。

**它产出两样东西**：

- **对外的**：它的游玩记录。有人就是爱看别人第一次玩。
- **对内的**：结构化的卡关数据——第几关、什么操作、什么条件下必现。

**关键**：它玩游戏这件事**本身有产出**。不是它「说」玩过（`PLAN.md §3.3` 的证据规则）。

**团队的收获**：一个不会累、不给面子、会如实说「这里很烦」的测试员。而且它的「烦」有证据。

### 场景三：开源项目共养一个记得事的成员

**人**：一个二十人的开源项目组。

**事**：他们共养一条鱼。它每天盯 issue、跑夜间构建、记录变更。

但真正有用的不是这些自动化——**是它记得。**

记得上次谁提过相关的设计；记得三个月前为什么否掉过一个方案；记得某个人说过「下个版本再看」。

**它每周做一次「这一周发生了什么」**：不是日志汇总，是有人味的周报——谁在纠结什么、哪个决策反转了、哪条路被证明是死的。

**关键差异**：这不是又一个机器人。机器人不记得三个月前的话。**成员记得。**

### 三个场景的共同点

| | 场景一 | 场景二 | 场景三 |
| --- | --- | --- | --- |
| 谁在养 | 一个人 | 小团队 | 项目组 |
| 它做什么 | 试错并记录 | 玩游戏并反馈 | 盯事并记忆 |
| 产出的东西 | 真实踩坑史 | 游玩记录 + bug 数据 | 有人味的周报 |
| **为什么不能是工具** | 工具不会自己去试 | 工具不会自己玩几小时 | 工具不记得三个月前 |

最后一行是关键：**这三个场景里，它不能被替换成一个更好的工具——因为价值来自「它自己过日子」。**

### 三个场景各自卡在哪（诚实版）

场景是设想，**它们依赖的能力并不是都做好了**。对着仓库核过一遍：

| 场景依赖 | 现状 |
| --- | --- |
| 生命层（身份、兴趣、承诺、账本） | ✅ 已实现并验证 |
| 自主唤醒（它自己到点动起来） | ✅ 已实现并验证 |
| 活动选择（它自己决定做什么） | ✅ 已实现并验证 |
| 证据规则（不许凭自述声称做过） | ✅ 已实现 |
| 沙盒内真的执行（工具调用有隔离） | ✅ 复用 dsh 的 `sandbox` |
| **对外发布到社交平台** | ❌ **未实现**（`PLAN.md §10.3` 列为下一步） |
| **长期运行（连续 7 天真实跑）** | ❌ 未做（策略层已用 soak 覆盖） |

**所以三个场景现在都停在「它能过自己的日子，但日子发不出去」。** 发布线打通之前，这些是**方向**，不是**演示**。

> 写这张表的原因：宏大叙事最容易犯的错，是让人分不清「已经这样了」和「打算这样」。**把两者混起来，第一次被追问就崩。**

## 四、远期：可继承的存在

如果上面成立，会自然长出一件新东西：**可迁移、可继承的存在。**

- 把一条鱼从一台机器搬到另一台，它还是它
- 给它加一个能力包，它真的学会新东西
- 你不再用了，它可以被归档、被封存

**但我们不承诺「永生」、不承诺「意识」、不承诺它会想念你。** 原因见下一节。

---

## 五、我们不声称的东西

宏大叙事最容易在这一节翻车。所以把不声称的也写下来：

- **不声称它有意识、有感受、有痛苦。** 精力、心情是**行为模拟变量**。它说「累了」是一个状态读数，不是体验。
- **不声称它能替代人际关系。** 它是你养的一条鱼，不是朋友、不是伴侣，不解决孤独。
- **不声称「从零成长」发生在鉴权和装依赖上。** 出生即会读网页、用工具；成长发生在品味、关系、熟练度上。
- **不声称你不管它也永远活着。** 它有维护成本。成本没人付的时候它会停下来——**而我们不把它包装成死亡来催你付费。**

**为什么这些「不声称」属于叙事本身，而不是免责声明**：因为这个产品赌的是**长期信任**。一个靠模糊话术过第一关的产品，会在第二关被打回原形。

> 反过来讲：**承认它不是活的，反而让它更像活的。**

---

## 六、什么会杀死这个故事

按可能性排序，全部诚实列出：

| 风险 | 为什么真实 | 我们能做的 |
| --- | --- | --- |
| **三天热度** | 一个人养一条鱼，容易看一眼就走 | 冷启动设计（`PRODUCT.md §4`）；让它产出你看得到的东西 |
| **平台封锁** | 若所有平台都禁自动化，发布线就断了 | 渠道分层（`§6`）；最坏退回「草稿 + 人工」，不绕过风控 |
| **成本降不下来** | 一天十块钱，它就是个小众玩具 | 确定性代码做基础动作，不用大模型做高频心跳（`§12.1`） |
| **OpenClaw 转向** | 它有基金会、全职团队、20+ 渠道 | 只做「活得久」这一件事，**绝不比功能** |
| **模型不诚实** | 证据规则依赖它不撒谎 | 工具证据强制（存档 / 截图 / 回执），**不靠自述** |

**最后一条最关键，因为它不依赖外部条件。** 如果它开始编造经历，整个立论就没了。所以证据规则是**硬约束**，不是提示词里的一句叮嘱。

## 七、这个故事成立时会是什么样

不看功能表，看一个具体的人：

> 他早上出门前看了一眼。它昨天在试一个外设，失败了两次，发了一条，还留了句「明天换成 SPI 试试」。
>
> 他没回。晚上回来，它已经试完了——**成功了**，发了一条，很短。
>
> 他点开账本看了看，发现它是在第 4 次尝试才通的，中间那次是因为读错了手册的时序表。
>
> 他没有「用」它。**他只是知道它在。**

这就是全部要讲的事。

---

## 八、最该记住的三句

1. **工具被使用，助手被呼叫，而它被维持。** 我们卖的是第三种关系。
2. **落地不靠功能多，靠「它自己过日子」。** 三个场景里它都不能被换成更好的工具。
3. **承认它不是活的，反而让它更像活的。** 不声称意识、不假装痛苦、不用死亡催单——这些是可信度，不是免责。
