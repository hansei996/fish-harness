这一版计划证明了什么

  • 打包与安装两关是真的过了：verify/pack-install.mjs 9/9， 15 files / 15 promised，进 CI 双平台。这不是纸面计划。
  • 阻断项是实测出来的：包名占用、形象被用、生态位被占，都取自 registry.npmjs.org 与 GitHub 的真实响应，不是推测。
  • 本机 registry 指向内网：这一点在旧文档里没有，实测才发现 —— 直接发布会上错 registry。

这一版计划没有证明什么

  • 「没人同时占」是假设：按关键词搜出来的，不是一家家读完确认的。
  • 没读 mofashi/dsh-life 的实现：不知道重合到什么程度。 在做完这步之前，改名与发布都不应该发生。
  • 没有 changelog / release notes 机制。
  • 陌生人演练完全没做 —— 而这才是「别人能装」的唯一验收。
  • 没有考虑「合作」这条路：如果 mofashi 在解决同一问题， 与它合并或协作可能比另起一个名字更好。这一步需要人来判断。

怎么复算

  • node verify/pack-install.mjs —— 两关的自动化验收
  • curl -sS https://registry.npmjs.org/<name> —— 名字是否可用，权威来源
  • npm config get registry —— 本机发布目标（当前是内网）
  • 逐步骤实测记录：docs/release.md · 生态复核：docs/MARKET.md §五之二
