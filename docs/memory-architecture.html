这张图证明什么

  • 接线全是公开扩展点：schedule · approval · tools · systemPrompt · webServer 五个注入， 加上 session/event 与 agent/inbox/claimed 两个监听。 没有一处改 dsh 核心。
  • 包名与行数都对过：18 个 dsh 包名取自本机真实安装； 9 个模块行数由 tools/facts.mjs 量出（合计 4834 行宿主 + 176 行客户端）。
  • 两边写的磁盘位置不同：dsh 按 projectKey(cwd)、我们按 lifeId —— 这就是「换目录、换会话，它还是同一个它」的根据。

这张图没有证明什么

  • 长期记忆会不会「糊」：跑三个月要不要总结、怎么总结，未验证。
  • 跨进程没有锁：dsh 有 session.lock，我们这层没有。
  • 真实长跑没做过：七天是压缩跑的，没有真实等待，也没跨真实进程重启。
  • 发布线一次真实发送都没有过：状态机与标识硬闸有断言，平台是真没连过。
  • UI 只有只读接口：/life/state.json 有测试，像素级没有。
