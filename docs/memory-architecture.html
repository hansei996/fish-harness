这张图证明什么

  • 五条接线都是公开扩展点：schedule · approval · tools · systemPrompt · webServer， 加上两个会话事件监听。没有一处改 dsh 核心。
  • 每个模块的行数与职责对着代码核过：合计 4834 行宿主代码 + 176 行客户端， 零自有依赖（只为兼容 npm CLI 与 Electron 两种运行时）。
  • 两类存储分桶方式不同：会话按 projectKey(cwd)、生命按 lifeId —— 这就是「换目录、换会话，它还是同一个它」的根据。
  • 快照有界：每轮注入 13 个字段；灌入 200 兴趣 + 200 承诺后仍是 690 字节，不随寿命增长。

这张图没有证明什么

  • 长期记忆会不会「糊」：跑三个月要不要总结、怎么总结，未验证。
  • 跨进程没有锁：dsh 有 session.lock，我们这层没有。
  • 真实长跑没做过：七天是压缩跑的，没有真实等待，也没跨真实进程重启。
  • 发布线一次真实发送都没有过：状态机与标识硬闸有断言，平台是真没连过。
  • UI 只有只读接口：/life/state.json 有测试，像素级没有。
