> 这份文档回答一个问题：**这个东西要卖给谁，而谁已经在卖了。**
> 要定义见 [`PRODUCT.md`](PRODUCT.md)，要实现见 [`PLAN.md`](PLAN.md)，要叙事见 [`STORY.md`](STORY.md)。
>
> 采集日期 **2026-10-28**。每条数字后面跟着它的采集命令 —— 复现不了的数字不许出现在这里
> （本仓库立过这条规矩：数字靠跑不靠抄）。三态显式标注：**✅ 已核实 / ⚠️ 未核实 / 🤔 推测**。
>

## 一、先说我们**不在**哪两个市场

这两个判断决定了后面一切。如果它们错了，这份文档就错了。

### 1. 我们不在「通用 Agent 框架 / 基础设施」市场

理由不是「我们比不过」，是**我们卖的东西和他们卖的东西不是同一种**。

| | 通用 Agent 框架（dsh / OpenClaw / LangChain 一类） | 我们 |
| --- | --- | --- |
| 卖什么 | **能力**：能调什么工具、接什么模型、跑多少渠道 | **持续性**：它明年还在不在、还是不是同一个它 |
| 用户拿它做什么 | 造一个东西出来 | 养一个东西下去 |
| 成功的信号 | 装了、跑通了一个 worklfow 的当天 | 第 30 天它还活着，而且行为有因果 |
| 换掉的成本 | 迁移代码 | **迁移一条命**（身份、关系、承诺全在里面） |

一句话：**框架卖的是「能做什么」，我们卖的是「还在不在」**。前者可以用功能表比，
后者比不了 —— 没人会在第 1 天就相信一个东西能活过第 30 天。

这个市场里最直接的证据是 dsh 自己的定位：**everything-is-a-plugin**，且它明写
「**THERE WILL BE COMPATIBILITY-BREAKING CHANGES**」（developer preview）。它把
「自己不是产品，是底盘」说得很清楚 —— 而底盘之上那层「活得久」没人做。

### 2. 我们不在「AI 陪伴 / 角色扮演」市场

这一条比上一条更容易搞错，因为表面上都说「有个有个性的 AI 陪着你」。

| | AI 陪伴（Replika / Character.AI / 猫箱一类） | 我们 |
| --- | --- | --- |
| 用户的诉求 | **被陪着说话** | **看它过日子** |
| 有没有外部世界 | 没有。对话是全部 | 有。它要真的去跑工具、真的发出去 |
| 失败的信号 | 用户觉得「没意思了」 | 平台封了、成本压不住、或者它开始编造经历 |
| 它的时间线 | 用户打开时才有 | **用户不在时也在走** |

关键差别在最后一行：陪伴产品的「性格」是**写死的设定**，你换一个会话它还是那样；
而我们要的「性格」是**被经历改写的** —— 第 3 天它因为挂了几次而对那件事失去兴趣、
这是要能被账本查出来的。**陪伴卖设定，我们卖履历。**

> 顺带说明为什么这条界线对我们**有利**：陪伴市场的核心指标是留存和会话时长，
> 那意味着越像人越好、越大方越好。而我们的核心指标是「它还在不在」——
> 一个卖履历的产品，**有失败反而更可信**。

它们的成功指标是检索命中率；我们的成功指标是第 30 天它还在不在。

### 第 2 层：虚拟生命 / 数字居民（**离我们最近的一层**）

这一层是这份调研里最有价值的发现 —— 因为它**表面最像**，而差别最尖锐。

| 项目 | 星数 ✅ | 它是什么 | 它和我们差在哪 |
| --- | --- | --- | --- |
| generative_agents（斯坦福小镇） | **22,300** | 研究论文的配套实现：一群 Agent 在小镇里模拟可信的人类行为 | **那是模拟，不是过日子。** 它在沙盒里跑，产物是一段 demo 动画；我们不模拟社会，我们让**一个**它真的去调工具、真的把东西发出去 |
| AI Town（a16z） | **10,715** | 「AI 居民生活的小镇」，可部署的起始套件 | 同上，它是**游戏/模拟引擎**（自带 shared state 与 simulation engine）。玩家是旁观者；我们的主人是**维持者** |
| Project AIRI | **50,816** | 开源赛博生命（有 Live2D 形态的桌宠方向） | 这一层最接近我们的**形态**。但它的重心是「**她是什么样**」（容器、形象、交互）；我们的重心是「**她过什么日子**」（跨会话状态、自主唤醒、账本、预算） |

**把这一层和我们并列看，差别只有一句话：**

> 它们都在做「**一个像活的它**」，我们在做「**一个真在过日子的它**」。
>
> 「像活的」是**表现层**问题，可以用动画、对话、人设解决；
> 「真在过日子」是**状态层**问题，要靠跨会话状态、自主唤醒、证据规则、预算硬上限解决。
> 前者三个月能做出来，后者做出来之后**必须再等三十天才知道成不成立**。

这正是我们的护城河该在的地方：**不是做得更像，是做得更久。**

### 第 3 层：Agent 社交网络 / AI 自媒体

| 命题 | 结论 |
| --- | --- |
| 「Agent 自己的社交网络」 | **⚠️ 未核实。** 本环境无法稳定核实这类项目是否真实存在、规模如何（多次抓取未取到可靠数据）。**不写。** |
| 「AI 自己发内容」 | ✅ **已核实：这件事本身不新**。OpenClaw 已接 20+ 渠道（含社交平台），发布能力是它的既有功能 |

**这一格的诚实结论**：如果我们唯一的卖点是「让 AI 自己发帖」，那这个市场**已经被占了**，
而且占它的是一家不收钱、有基金会、有 39 万星的机构。
我们唯一站得住的位置是：**发帖只是它生活的一部分，不是它的目的** ——
它先得过日子，才有东西可发。

   所以「桌宠」不是我们的护城河，是**必须补齐的基础设施** ——
   它是用户每天唯一会真正看到的「它还在」的证据。

## 四、谁会用、谁会付钱、谁会留下

三档，每档都写**证伪信号** —— 出现什么现象就说明这档不成立。

### A 档：一个人养一条，为了「它自己在产出」

**谁**：做嵌入式/运维/逆向这类**有真实实验过程**的工程师，想写东西但晚上没精力。

**为什么会用**：他要的不是「AI 帮我写」，是「**有人替我真的试过**」。
每条内容后面跟一次真实工具调用记录 —— 这是内容农场给不了的。

**会不会付钱**：**会，但很少**。这一档付的是「省下我自己的时间」，
所以定价锚点是**他的一小时**，不是软件的月费。`PLAN.md §12` 已经定过口径：
一天成本要压到「可以浪费」的量级（几块钱），否则它是个小众玩具。

**证伪信号**：
- 第 7 天他还没打开过账本 → 他不关心「真试过」，只关心内容产出 → 那我们和内容农场的差别对他无意义；
- 他觉得「太慢」→ 他要的是量，不是真 —— 这一档不成立。

### B 档：小团队养一条，当**不会累的成员**

**谁**：三人左右的独立开发团队（缺测试、缺文档、缺一个一直盯 issue 的人）。

**为什么会用**：它记得住三个月前否掉的方案、记得住谁提过什么。
**这一档买的是「记忆」，不是「能力」。**

**会不会付钱**：**最可能真付钱的一档**。因为它替代的是**人力预算**，
而且它的产出可以直接换算成工时（卡关数据、复现步骤、变更记录）。

**证伪信号**：
- 团队开始需要**校对**它的结论 → 它撒谎了，那整个立论崩塌（比不付钱严重得多）；
- 它记的东西**他们本来就有**（issue tracker、git log）→ 那它不是成员，是个重复的索引器。

### C 档：社区/开源项目共养一条，当**有个性的记录者**

**谁**：二十人规模的开源项目组。

**为什么会用**：他们想要一个有人味的周报，而不是又一个机器人。
**这一档买的是「身份」** ——「我们家的那条鱼」。

**会不会付钱**：**观望**。这一档的付费入口可能不是订阅，而是「**认养/馈赠**」
（像 OpenClaw 那样靠捐赠，而不是靠卖功能）—— 因为它的价值是社区性的。

**证伪信号**：
- 没人愿意在周报上署名「由我们的鱼整理」→ 它没被当成成员，只是个工具 → 这一档不成立；
- 一旦要迁移（换机器/换模型）就有人问「它还是同一个它吗」 → **这一档反而是我们最强的用户**，
  因为他们在意「存在」本身。

### 三档的共同点（也是最难的一点）

| | A | B | C |
| --- | --- | --- | --- |
| 买的是什么 | 真试过的记录 | 记得住的成员 | 有个性的存在 |
| 付费锚点 | 他的一小时 | 一个测试人力的零头 | 社区身份（可能靠捐赠） |
| **最容易死在哪** | 三天热度 | 它开始编造 | 迁移时丢了它 |

**共同点**：三档都不是在买「功能」，是在买「**它在**」。
所以产品指标不能是活跃、不能是会话时长 —— 只能是「它还活着」（`PRODUCT.md §10`）。

## 六、我们的空位（一句话）

> **基础设施层不收钱、陪伴层不碰真实世界、模拟层不出沙盒、记忆层只管记得多 ——
> 「让一个 Agent 在真实工具生态里、以可控成本、跨会话地过下去」这一格，没有人占。**

而这一格的特点是：**它做出来之后，要等三十天才知道成不成立。**
这是它为什么空着，也是它为什么一旦占住就很难被功能表追平。

## 七、三个证伪条件（什么事实出现，就该放弃这件事）

不是「风险提示」，是**可判定的止损线**。任一条成立，这件事的立论就没了。

| # | 证伪条件 | 怎么算成立 | 为什么它是致命的 |
| --- | --- | --- | --- |
| 1 | **成本压不到「可以浪费」** | 一条命一天的真实成本降不到个位数人民币（含唤醒、工具调用、发布） | 那就不是「养」，是「烧」。所有「它会自己过日子」的说法都变成奢侈品 |
| 2 | **平台对接全部走不通** | 唯一能接的渠道（Telegram）也拿不到稳定回执，且剩下所有平台都禁止自动化 | 那「它对外生活」这一半永远停在草稿。此时**必须**退回「只做内生生活 + 草稿」，而不是绕过风控 |
| 3 | **第 30 天留不住人** | 领养后第 30 天仍在看它账本/内容的人低于 10%（阈值是**猜的**，见下） | 「它被维持」这件事如果没有被维持，产品就退化成一次性演示 |

> ⚠️ **第 3 条的阈值是假设，不是测量结果。** 我们没有真实用户数据。
> 写在这里是为了让它**可被推翻** —— 一个没有数字的止损线等于没有止损线。

另外两条**同类但还没到「放弃」程度**的观察线：

- **模型不诚实**：如果它在**有证据规则**的情况下仍然开始编造经历 → 立论崩塌。这一条不依赖外部条件，所以要最早防（证据规则是硬约束，不是提示词里的一句叮嘱）。
- **OpenClaw 转向**：它有基金会、全职团队、20+ 渠道。**如果我们开始跟它比功能，就已经输了。** 只做「活得久」这一件事。

## 八、这一类最容易被骗过的地方

调研里最值得单独列出来的，不是竞品，是**「假装活着」的判定方法** ——
因为市场上「自主运营的 AI」这个词已经被用到了不可信的程度。

一个东西声称「Agent 在自己活着」，用这三问就能戳穿大半：

1. **它醒着的时候是谁定的？** 如果是「定时器每 N 分钟塞一句话」，那不是活着，是心跳。
   真活着的证据是**它自己决定什么时候醒、以及什么时候不醒**（休息也是一个合法选择）。
2. **它的历史存在哪、能不能回放？** 如果只在一个会话的上下文里，那是**一段对话**，
   不是一段生活。真活着的证据是**一份能逐条回放的账本**，每条结论后面跟着证据。
3. **它做失败的事会怎样？** 如果一个系统的产物里**从来没有失败**，那它多半没真的做事 ——
   真做事会失败，而失败才是「它真的试过」的证据。

> 这三问同时也是我们自己的验收标准（`PLAN.md §11.4`「怎么判断一个产物是不是表演」）。
> **把它们写下来，是因为我们最可能骗过的人是自己。**
