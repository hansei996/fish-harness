# 它的一周：一份真实跑出来的七天日志

> 这份文档只讲一件事：**「连续七天」不再是说法，而是一条可复现的命令。**
>
> 跑法：`node tools/life-week.mjs`（约 0.1 秒，不需要 dsh，不需要模型）
> 守它的断言：`node verify/life-week.mjs`（16 项）
>
> 日期：2026-10-27 · 种子 20261027

---

## 一、为什么要有它

`docs/PRODUCT.md §6 阶段 A` 的产出物写着「一份『真实跑 7 天』的日志」。它缺了很久，而缺它有代价：

- **soak 只验了唤醒策略的算术** —— 不跳日、不落静默、不超预算。那些是「闹钟会不会响」。
- **没有任何东西验过「日子本身」** —— 七天里它有没有真的在做事、失败会不会留下后果、兴趣会不会累积、承诺会不会兑现。

而这个产品的全部主张是**累积**：第三天能看出偏好、第七天行为有因果。
一个只被单日演示过的东西，没资格说这句话。

**它是怎么做到 0.1 秒跑七天的**：不等待。它复用生产的 `lib/wake.js`（定闹钟）、
`lib/choose.js`（排序）、`lib/store.js`（落盘），只把时钟换成可注入的
（这就是 `store.js` 构造函数里 `clock` 选项存在的理由）。

## 二、它证明的

上面那条命令的输出（节选，逐字来自实跑）：

```
  大肥鱼的一周 · 7 天 · 账本 90 条
  ────────────────────────────────────────────────────
  2026-10-27
    08:00  ◦ 大肥鱼出生了
    08:00    答应了一件事：把《地底 38 层》的打法写进自己的笔记（2026-10-29 前）
    09:15  ▸ 开始：看看「机械键盘手感」的更新（因为 ... 只观察过 1 次，值得多看一眼）
    10:29  · 没做成：看看「机械键盘手感」的更新：资料对不上，记下来换个来源｜证据 save:aaf500
    10:29  → 留下了明天要做的事：换个打法再试一次「看看「机械键盘手感」的更新」
    13:18  ✓ 做成了：看看「像素矿工小品」的更新｜证据 link:8f936a
    14:47  ○ 选了休息 —— 今天没有非做不可的事
      ── 自己醒 6 次 · 起 5 件事 · 成 4 · 败 1 · 休息 1
  ...
  第七天它是什么样：
    兴趣 像素矿工小品  0.95  （观察 17 次，来源 experience）
    兴趣 机械键盘手感  0.95  （观察 12 次，来源 experience）
    承诺：兑现 1 件，还欠 0 件
```

具体到可检查的六条（`verify/life-week.mjs` 全部守着）：

| 断言 | 它排除掉的假象 |
| --- | --- |
| 七天，每天都有记录 | 「跑了七天」其实只有一天有输出 |
| 每天要么有真活动、要么是**明确的**休息 | 空白的一天被算成平静的一天 |
| 从不超出每日唤醒预算（6） | 第一版一天醒了 10 次，且看起来「很活跃」 |
| 一天之内时间从不倒流 | 第一版出现过 10:52 后面接 10:48 |
| 失败发生了，而且留下了下一步 | 「留下明天的钩子」是空转的 |
| 每次收尾都带证据 | 「做成了」可以没有凭证 |
| 承诺被兑现 | 承诺只是写下来当时好看 |
| 同一天不会全部花在同一件事上 | 一天 6 次同一件事会显得很勤快 |
| 同一个种子给出同一周 | 结论无法被复核 |

## 三、它抓出了什么

跑通七天才暴露的问题，全部是「单日演示里看不见、断言也断言不到」的那一类。三个在
`PLAN.md §6.2` 有详细表格，这里只给一句话：

1. **重复没有代价** —— 做完会刷新 freshness，于是同一件事永远排第一。
2. **探索只有入口没有出口** —— 越熟悉越值得做，于是七天没探索过第三件事。
3. **「留下一个明天要继续的事」是死代码** —— `choose.js` 有分支读 `activity.next`，
   但全仓库没有一处写它。

修的过程中还发现第四个：**交接写下来了，但从来没被履行**（`next` 得 0.349 分，
休息是固定 0.35）。这一条**故意没改**，理由写在 `PLAN.md §6.2` 的末尾。

> 这四个里有三个是**产品级缺陷**，不是代码 bug：程序一直运行正常，只是它过的日子
> 和文档里承诺的日子不是一回事。**这正是「连跑几天」这类验证唯一能提供的东西。**

## 四、它**没有**证明的（重要）

别把这份日志读成承诺。三件事它做不到：

1. **没有调用模型。** 选活动的是排序器（`lib/choose.js`），不是模型。
   所以它证明的是「生活骨架成不成立」，**不是**「模型会不会照这个骨架过日子」。
   后者恰恰是 `PLAN.md §11.2` 那条还没打勾的决策门 —— 而那条门的原话就是
   「不是 soak 模拟」，写的就是这种跑法。
2. **七天是压缩跑的。** 没有真实等待，所以不覆盖真实调度器的投递、进程重启、
   dsh 升级这些只在真机上出现的事。
3. **失败是注入的。** 哪个话题第一次会失败写死在 `FAILURE_TOPICS` 里，不是真跑出来的。
   真实结果由工具调用的真实产出决定（`life_finish_activity` 的证据）。
4. **它只有两个种子兴趣。** 真实模型会 `life_note_interest` 发现新东西，这份日志里没有 ——
   所以「探索」的收益在这里被低估了，不是被证明。

## 五、怎么读它、怎么改它

```sh
node tools/life-week.mjs                    # 默认七天，打印
node tools/life-week.mjs --days 14          # 更久
node tools/life-week.mjs --seed 7           # 换一周（结论应随之变化，但不该变坏）
node tools/life-week.mjs --json             # 供程序消费（含七项分数明细）
```

它进 CI（ubuntu + windows 各一遍）。跨平台会暴露的东西它尤其容易撞上：
路径、时区、本地日历日 —— 而「每天」这个概念本身就是本地日历日。

> **一句话记住它的位置**：它是**阶段 A 的证据**（状态可解释），
> 不是阶段 B 的（有人会想养）。两者之间隔着一次真实的、有模型的运行。
