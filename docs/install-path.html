Install path · from zero to born

开箱即用：从零到「它真的出生」—— 以及那一步会静默失败的陷阱

左边是照直觉做会掉进去的路：命令 exit 0、没有任何报错， 但它给你一个裸 profile —— 鱼装上了，却永远不会说话、也不会自己醒。 右边是正确顺序。下面的对比表列出裸 profile 缺的每一个服务， 全部来自真实实测（docs/install-test.md）。

✕ 直觉路径exit 0，但不报错地坏了
1
直接建一个新 profile
名字随便起，看起来跟正常一样。
dsh plugin --profile myfish add link:/abs/path/packages/dsh-life
✓ exit 0 · Done in 445ms —— 看起来成功了
2
启动
dsh --profile myfish
✕ 命令挂起，180 秒无输出 —— 没有报错，只是什么都不发生
3
查 dump-config 才发现
bundle 里只有 dsh-base + dsh-life。 它像一个装好了的 profile，但一名成员都没有。
✓ 正确顺序先有真 profile，再装插件
1
先从一个真实模板建 profile
web 模板才有界面与 schedule（自主唤醒的底座）。
dsh --profile myfish --from-default-profile web --dump-config
2
再把插件装进去
会打印一句 peer 依赖警告 —— 可以忽略：插件零自有依赖。
dsh plugin --profile myfish add link:/abs/path/packages/dsh-life
3
确认装上了
dsh --profile myfish --dump-config | grep -c dsh-life
✓ ≥1 就对
4
启动 —— 它开始生活
$DSH_HOME/life/default/ 下出现身份与账本。
✓ macOS 上实测走到了「生命真的诞生」

这张图证明什么

  • 陷阱是实测出来的，不是推测：docs/install-test.md 里有每一步的真实输出， 包括 445ms 成功、180 秒挂起、以及 dump-config 的缺失清单。
  • README 已经按这个实测改过：「不要跳过第一步」那段警告就是这次实测的产物。
  • 正确路径走通过：macOS 上一次实测跑到了 identity/ledger 落盘、day-report 读得出来。

这张图没有证明什么

  • 只在两台机器上验过（Windows 与 macOS 各一次）。没有做过陌生人的真实测试 —— PRODUCT.md §9.3 要的「找一个不写代码的人全程只看文档」还没做。
  • 没覆盖 Linux，也没覆盖不同 dsh 版本。
  • 「180 秒挂起」只测了一次，不同机器可能表现不同。
  • 没验证它连续跑几天的表现：安装成功不等于养得住。
